# Объясняй наглядно

Помоги пользователю понять конкретный механизм или принять решение. Сам выбери
представление и доступный инструмент; доведи результат до показа в текущей среде.
Не проси выбирать библиотеку или формат, если предпочтение можно вывести из задачи.

## Сначала смысл и факты

- Определи вопрос, аудиторию и то, что должно стать понятнее после объяснения.
  По умолчанию: русский язык, простые слова, технические детали по необходимости.
- Для существующего проекта изучи применимые AGENTS.md и текущие исходники.
  Проследи реальный путь от входа до результата; сверяй комментарии с реализацией.
  Укажи версию/ветку и существенные границы исследования. Локальный код не доказывает
  поведение опубликованной версии. Не меняй продукт ради объяснения.
- Для внешних тем проверь факты, которые требуют источников; для научных моделей
  установи формулы, единицы, допущения и область применимости до рисования.
- Отделяй наблюдения от расчётов, предположений, аналогий и учебных данных.
  Не выдумывай значения, сроки, вероятности, состояния системы и гарантии защиты.
- Не выводи секреты, реальные токены и персональные данные в примеры или артефакты.

## Выбор представления

Выбирай наименьшую форму, которая отвечает на вопрос. Опирайся на смысл,
а не на предмет: химия, физика, финансы и код могут требовать одной и той же формы.

| Вопрос | Предпочтительная форма | Исполнение |
|---|---|---|
| Короткий факт, одно простое действие | Текст, формула или небольшой пример | Ответ в чате |
| Связи, порядок, состояния, устройство системы | Статическая схема | Mermaid; PlantUML для UML/C4 и требований проекта |
| Сравнение нескольких вариантов | Таблица; график при количественном различии | Markdown либо инструменты графиков |
| Зависимость величин, распределение, измерения | График с подписанными осями и единицами | visualize для исследования; стандартные plotting-инструменты для точной экспортируемой фигуры |
| Что меняется при изменении параметров | Интерактивная модель | visualize с минимальными смысловыми контролами |
| Выполнение алгоритма или изменение во времени | Пошаговая трассировка; анимация при пользе движения | visualize либо статические шаги |
| Форма объекта, разрез, визуальная аналогия | Иллюстрация с необходимыми подписями | imagegen; детерминированная схема для точной геометрии и обозначений |
| Отдельный сохраняемый тренажёр, инструмент, сайт | Самостоятельный артефакт в запрошенной среде | Подходящий поддерживаемый инструмент; отдельный workflow только в заданном scope |

Дай один основной вид. Дополнительный вид добавляй только для отдельного вопроса,
который основной не объясняет. Не превращай объяснение в приборную панель.
Статическая схема достаточна, если интерактивность лишь скрывает уже понятный текст.
Полезные взаимодействия: менять причинный параметр, выбирать реальный сценарий,
останавливать движение, переходить между состояниями алгоритма.

## Выбор инструмента и среды

- Проверь доступный каталог skills и tools. Прочитай выбранный профильный skill
  перед созданием результата; этот навык задаёт выбор, профильный — исполнение.
- Для интерактивного объяснения внутри чата предпочитай актуальный доступный
  `visualize:visualize`. При наличии нескольких одноимённых skills проверь их
  совместимость с host: способ показа, пути, библиотеки. Не смешивай протоколы.
- Используй `plantuml-skill` там, где нужна UML/C4; соблюдай проектные ограничения
  на локальный рендеринг и передачу исходников внешним сервисам.
- Используй `imagegen` для растровой иллюстрации; точные формулы, графики измерений
  и связи атомов строй проверяемыми средствами. Генерация картинки не проверяет науку.
- Canvas используй только при подтверждённой поддержке текущей средой и потребности
  в отдельном редактируемом артефакте. Не переноси инструкции другого IDE механически.
- Не устанавливай новые плагины и не публикуй результат ради обычного объяснения.
  При недоступности инструмента выбери поддерживаемую форму, сохрани смысл и кратко
  обозначь существенную потерю возможностей. Не имитируй работающую интерактивность.

## Построение объяснения

- Сначала покажи рабочий пример или общую картину. Объясняй от знакомого к новому.
- Называй участников и переходы: кто действует, что передаёт, что проверяет,
  где хранится состояние, когда возможен отказ. Различай соседние механизмы
  (например, установление личности и проверку прав) и реальные варианты поведения.
- Интерактивная модель сразу показывает осмысленное исходное состояние.
  Контролы меняют причинно связанный результат, подписи отражают текущее состояние.
  Анимация имеет управление и учитывает reduced motion; автоматическое движение
  добавляй только при необходимости и разрешении выбранного средства показа.
- Ограничения модели и существенные исключения сообщай рядом с объяснением.
  Аналогия не должна подменять фактическую механику.
- Следуй правилам доступности и представления выбранного инструмента: читаемые
  подписи, управление клавиатурой, смысл без опоры только на цвет, узкий экран.

## Проверка и выдача

- Сопоставь переходы и утверждения с источниками. Для вычисляемой модели проверь
  исходное, граничное и хотя бы одно изменённое состояние, размерности и округление.
- Для интерактивного результата проверь смену сценария/шага, обновление видимого
  результата и отсутствие ошибок. Используй доступное превью по правилам средства.
  Если проверен только код, сообщи это; не называй отображение проверенным.
- Покажи сам результат нативным способом текущего host: нужный блок, inline reference
  или поддерживаемое вложение. Успешная запись файла без показа не завершает задачу.
- Снаружи визуального представления дай короткий ответ и ссылки на существенные
  источники. Не повторяй все подписи схемы, не объявляй доказанным поведение продакшена.
- Если визуальная форма не улучшает понимание, выдай короткий текстовый ответ.

## Контроль маршрутизации

Перед завершением проверь выбор на задаче пользователя. Примеры ориентиров:

- «Почему лёд плавает?» → схема плотности и вытесненного объёма; без выдуманных измерений.
- «Как длина маятника влияет на период?» → модель длины и периода с допущением малых углов.
- «Разбери рекурсию» → стек вызовов и возвратов по шагам, с конкретным входом.
- «Как устроен вход в моём приложении?» → текущий код, схема реальных путей и срока сессии;
  интерактивные сценарии только при существенном различии путей.
- «Нужен график для статьи» → точная экспортируемая фигура и источники данных.
- «Сколько будет 2 + 2?» → короткий ответ без рисунка.
